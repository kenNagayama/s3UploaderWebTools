# ダッシュボード開発計画書

## 1. 概要

社内向けに Tableau で行っていたダッシュボード開発の知見を活かし、Amazon S3 静的ウェブサイトホスティングとサーバーレス構成を中心とした、より軽量で柔軟なダッシュボードシステムを開発する。

## 2. 実現したいこと

現場（技セ・メセ）の社員が、トロリ線の摩耗状態を以下の2つの視点で確認できるようにする。

1. **俯瞰的な確認:** 路線単位で見た際に、摩耗の進行が早い箇所や、局所的に摩耗が進んでいる箇所を直感的に把握する。
2. **詳細な推移確認:** 特定の電柱・ハンガ位置における摩耗の時系列変化を確認する。

## 3. 技術的な構成条件

### 3.1 システムアーキテクチャ

* **フロントエンド:** Next.js (SSG/Export) on Amazon S3 (静的ウェブサイトホスティング)
* **バックエンド (API):** Amazon API Gateway + AWS Lambda
* フロントエンドから直接 Athena を叩くのではなく、API Gateway 経由で Lambda を呼び出す構成とする（セキュリティ向上およびビジネスロジックの隠蔽）。


* **データソース:** Amazon Athena (Glue Data Catalog)

### 3.2 ダッシュボードのUI/UX仕様

画面を左右に分割したレイアウトを採用する（プロトタイプ画像：`spec/sample/sample-dashboard.png` 参照）。

#### A. 画面左側：ヒートマップ（俯瞰用）

* **軸構成:**
* **横軸（列）:** 測定年月日
* **縦軸（行）:** 場所情報（階層構造：電柱番号 > ハンガ位置 1H〜14H）


* **描画ロジック:**
* **Unpivot処理:** CSVの横持ちデータ（`摩耗_最小値_1`〜`14`）は、データ処理用 Lambda 側で縦持ち形式に変換し、フロントエンドには加工済みの JSON を渡す。
* **色分け:** トロリ線の残存直径（摩耗値）に応じてヒートマップの色を変化させる。
* **赤系統:** 摩耗が進行している（残存直径が小さい）
* **青系統:** 摩耗が少ない（残存直径が大きい）


* **基準値の動的判定:** トロリ線種によって新品時の直径が異なるため、線種データを参照して判定する。
* 線種 `X, Y, Z, G, H, I, K, L, M`: 新品径 **15.49mm**
* 線種 `スペース, B, C`: 新品径 **12.34mm**




* **技術選定:**
* 大量のデータポイント（日付 × 電柱数 × 14ハンガ）を描画するため、描画パフォーマンスに優れた **Canvasベースのライブラリ**（例: Chart.js, Nivo Canvas版など）を採用する。



#### B. 画面右側：折れ線グラフ（詳細分析用）

* **動作:** 左側のヒートマップ等で「電柱番号」を選択すると、その箇所の詳細データを表示する。
* **軸構成:**
* **横軸:** 測定年月日
* **縦軸:** 摩耗の最小値 (mm)


* **表示内容:** 選択された電柱における、ハンガ位置（1H〜14H）ごとの摩耗推移を重ねて表示する。

### 3.3 データ処理フロー

1. **データストア:** S3 上の CSV データ（Glue テーブル定義済み）。
2. **データ取得・加工:** AWS Lambda が Athena にクエリを投げ、取得したデータをフロントエンド描画用に加工（Unpivot処理含む）してレスポンスする。
* *※既存の簡易処理Lambdaをエンハンスして利用。*



### 3.4 セキュリティ・ネットワーク

* **アクセス制限:**
* 開発フェーズ (MVP): 認証なし（社内ネットワーク内からのアクセスを想定）。
* 本番運用フェーズ: Secrets Manager で管理された IP アドレスリストに基づくアクセス制限（WAF等）を実装。（今回はまだ実装しない）


* **将来構想:** Entra ID を利用した社内ユーザー認証の導入。（今回はまだ実装しない）

## 4. 将来的な拡張性 (Future Scope)

MVP開発完了後、以下の機能を検討する。（今回はまだ実装しない）

1. **異常検知・アラート:**
* 減少傾向だった摩耗値が上昇に転じた場合のアラート。
* 管理値（`摩耗_管理値－P0/P1/P2`）を下回った箇所のハイライト。
* AI/MLを用いた異常予測。


2. **トロリ線張替への対応:**
* 測定期間中にトロリ線が新品に交換された場合、グラフ上でそれが分かるように「張替マーカー」を表示する機能を追加する（MVPでは線種マスターに基づく静的判定のみとする）。
